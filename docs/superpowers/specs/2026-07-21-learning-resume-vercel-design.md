# 学习续读与 Vercel 部署设计

## 目标

让学习者在同一浏览器再次打开课程时，自动回到上次阅读的知识单元；只有主动选择“从头开始”时才返回课程起点。同时将静态课程部署到 Vercel，提供可公开访问的链接。

## 范围

- 保存当前阅读到的章节、知识单元和单元内相对位置。
- 页面重新打开后自动恢复阅读位置，不播放滚动动画。
- 在常驻导航中提供“从头开始”，经过二次确认后只清除阅读位置。
- 保留已有答题、错题、收藏词卡和间隔复习记录。
- 保留复习中心现有的“清空学习记录”，用于彻底清除全部学习数据。
- 部署当前 Vite 静态站点到 Vercel，并验证公开链接。

本阶段不实现账号、数据库或跨设备同步。跨设备同步作为后续独立功能建设。

## 数据设计

现有 `LearningState` 升级一个版本，增加 `readingPosition`：

- `chapter`: 当前章节编号。
- `unitId`: 当前知识单元的稳定 DOM 标识。
- `unitProgress`: 当前视口相对该单元的阅读比例，范围为 0 到 1。
- `updatedAt`: 最后更新时间，用于后续同步扩展和调试。

旧版浏览器数据迁移时保留答案、复习和收藏，并为 `readingPosition` 使用空值，不能因为状态版本升级丢失已有学习记录。

## 位置记录

页面用 `IntersectionObserver` 观察带稳定 ID 的知识单元，选择最接近阅读焦点的可见单元。滚动和视口尺寸变化时以节流方式更新单元内相对位置，避免每个滚动事件都写入 `localStorage（本地存储）`。

只在用户已经进入课程区域后记录位置。首页介绍、全局知识图和复习中心不会覆盖最近的课程位置。

## 自动续读

应用完成首次布局后读取 `readingPosition`。目标单元存在时，先定位到该单元，再根据保存的相对位置补偿滚动。恢复使用立即定位，不使用平滑滚动，避免长页面在打开时发生明显移动。

若保存的单元已被内容更新移除，则退回保存章节的开头；章节也无效时回到第一章。恢复过程只执行一次，并避免恢复动作本身反复写入位置。

## 从头开始

顶部常驻导航提供“从头开始”命令。点击后显示二次确认，确认后：

- 清空 `readingPosition`。
- 立即回到第一章开头。
- 不删除答题、错题、收藏词卡或复习日程。

复习中心的“清空学习记录”保持原有含义，并同时清除阅读位置。

## 组件边界

- `learningStore`: 状态迁移、位置更新和位置重置的纯函数。
- `LearningProvider`: 暴露保存与重置阅读位置的动作。
- `useReadingProgress`: 负责观察知识单元、节流记录和首次恢复。
- `AppHeader`: 展示“从头开始”命令和确认界面入口。
- `CourseApp`: 协调章节跳转、自动恢复和手动重置。

## 部署

使用 Vercel CLI 将 `vite build` 生成的静态站点部署为 production。Vite 单页应用当前没有客户端子路由，不需要额外 rewrite。部署前运行完整测试和生产构建，部署后请求公开 URL 并检查 HTTP 200、页面标题和主要课程内容。

## 测试

- 存储测试：旧版状态迁移、位置保存、只重置位置、彻底清空。
- 组件测试：有历史位置时恢复；无历史位置时停留首页；从头开始需确认且不清空答题。
- 端到端测试：滚动到后续知识单元、刷新、回到相同单元；选择从头开始后回到第一章。
- 回归测试：现有内容校验、单元测试、响应式测试和生产构建全部通过。

## 失败处理

浏览器禁用或限制 `localStorage（本地存储）` 时，课程仍可正常阅读，但不会保存位置。保存位置损坏、目标不存在或布局计算异常时，安静地退回第一章，不阻断页面。
